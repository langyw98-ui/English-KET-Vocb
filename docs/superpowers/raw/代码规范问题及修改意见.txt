  ## 一、 关键问题（Critical / P0，必须修）                                                                 
                                                                                                            
  ### 1. KetIntent 类型契约不一致（CLAUDE.md §2.2）                                                         
                                                                                                            
  • 现象确认：                                                                                              
      • src/flow/ket_partner/state.py:5 声明为 Literal["translate", ...]（写成了 "translate"）。            
      • 但 dialogue_domain.py:29 的 LLM Pydantic Schema、vocab_domain.py:208 以及 graph.py:16               
      的路由代码中全都在使用 "translation"。                                                                
  • 风险：类型注解中 "translate" 是永远触发不到的死值，导致 mypy                                            
  无法捕获隐式类型错配，路由存在静默失败隐患。                                                              
  • 修复方案：将 state.py:5 的 KetIntent 修正为：                                                           
    KetIntent = Literal["translation", "asks_meaning", "idk", "off_topic", "non_compliant"]                 
                                                                                                            
  ──────                                                                                                    
  ### 2. LLM 异常元组混入代码 bug 类型（CLAUDE.md §1.5）                                                    
                                                                                                            
  • 现象确认：在 vocab_domain.py (L142, L176, L197)、dialogue_domain.py (L42, L85,                          
  L204)、sentence_domain.py (L186, L360)、agent.py (L61) 9 处跨边界捕获中，均写成了：                       
    except (TimeoutError, RuntimeError, ValueError, AttributeError, TypeError) as e:                        
                                                                                                            
  • 风险：ValueError / AttributeError / TypeError 是典型的代码                                              
  bug（如空指针、字段访问错位），捕获它们会将真正的代码 bug 误当成 "LLM 网络失败" 静默兜底。                
  • 修复方案：瘦身异常元组，移除代码 bug 类型，仅保留外部 IO/网络/超时异常：                                
    except (TimeoutError, RuntimeError) as e:  # 或外部 SDK 的特定 APIError                                 
                                                                                                            
  ──────                                                                                                    
  ### 3. src/api/app.py:70, 77 裸 except Exception（CLAUDE.md §1.1）                                        
                                                                                                            
  • 现象确认：app.py 的应用关闭（shutdown）路径中两处直接写了 except Exception as e:。                      
  • 修复方案：显式捕获可能发生的具体关闭异常：                                                              
    except (RuntimeError, OSError, asyncio.TimeoutError) as e:                                              
                                                                                                            
  ──────                                                                                                    
  ### 4. sentence_domain.py:444 跨边界裸 4 元组（CLAUDE.md §2.11）                                          
                                                                                                            
  • 现象确认：generate_with_fallback(...) 签名返回 tuple[str, ValidationResult, str,                        
  str]。调用方只能按索引 res[0], res[1] 访问，顺序颠倒无法被编译器识别。                                    
  • 修复方案：定义带命名字段的只读 dataclass：                                                              
    @dataclass(frozen=True, slots=True)                                                                     
    class SentenceGenerationResult:                                                                         
        sentence: str                                                                                       
        result: ValidationResult                                                                            
        target: str                                                                                         
        context: str                                                                                        
                                                                                                            
  ──────                                                                                                    
  ### 5. src/flow/common.py:57-82 LLM 服务硬编码无 DI（CLAUDE.md §10.8 / §10.9）                            
                                                                                                            
  • 现象确认：llm_max 和 llm_flash 作为模块级全局变量直接硬编码实例化，业务代码依赖注入困难，单测只能       
  monkeypatch 全局变量。                                                                                    
  • 修复方案：                                                                                              
      1. 定义 LlmService 依赖包装类或接口 Protocol。                                                        
      2. 在 build_agent 工厂与依赖注入层传入 llm_service: LlmService | None = None，默认实例化全局实现。    
                                                                                                            
  ──────                                                                                                    
  ### 6. sentence_domain.py:552-576 修改入参（CLAUDE.md §3.1）                                              
                                                                                                            
  • 现象确认：apply_multiword_target_patch(target, sentence, result) 直接在函数内部修改了 result.           
  words_used 和 result.non_ket_words 的列表。                                                               
  • 修复方案：遵守纯函数原则，返回复制并更新后的 ValidationResult 新对象：                                  
    def apply_multiword_target_patch(target: str, sentence: str, result: ValidationResult) ->               
  ValidationResult:                                                                                         
        # ... 计算 new_words_used 和 new_non_ket_words                                                      
        return result.model_copy(update={"words_used": new_words_used, "non_ket_words":                     
  new_non_ket_words})                                                                                       
                                                                                                            
  ──────                                                                                                    
  ### 7. sentence_domain.py:434-550 超长函数（CLAUDE.md §4.1）                                              
                                                                                                            
  • 现象确认：generate_with_fallback 达到 117 行，混杂了造句生成、重试、溢出降级与换词策略。                
  • 修复方案：拆分为 3 个职责单一的子函数：                                                                 
      • _generate_with_retry(...)                                                                           
      • _handle_overflow_fallback(...)                                                                      
      • _switch_target_or_accept(...)                                                                       
                                                                                                            
  ──────                                                                                                    
  ### 8. src/flow/ket_partner/agent.py 浅层透传（CLAUDE.md §10.3 / Middleman）                              
                                                                                                            
  • 现象确认：KETPartnerAgent 类中 12 个节点方法全是 return await nodes.xxx(state, config,

      中直接绑定节点）。
